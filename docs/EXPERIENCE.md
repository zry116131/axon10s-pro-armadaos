# 从 Android 手机到 ArmadaOS：本机移植经验

本文记录一台 Axon 10s Pro 的实际探索。结果依赖它的引导器、原厂硬件描述、固件及存储布局；同一 SoC 并不意味着不同手机可以共用镜像。

## 1. 先确定系统分层与验证目标

这里运行的是原生 ARM64 Linux 内核和 ArmadaOS 用户空间。板级内核解决屏幕、触摸、存储、供电等问题，桌面与 Steam 的兼容组件处理会话及游戏。原厂 Android 内核和设备树是重要参考，但提取到这些文件之后，仍需将相关描述接到目标内核的驱动框架。

最有用的第一批结果是：可观测的启动、可恢复的 USB 调试、内部存储访问。黑屏、Logo 卡住与 CPU 没有执行目标内核并不是同一个结论。应记录每次试验的镜像哈希、配置、启动方式及可确认的阶段。

## 2. 极简内核会引入额外变量

早期大量工作围绕极简配置和入口检查点展开。检查点帮助证明了执行位置，却没有直接解决完整系统的稳定性。后来改为标准 ARM64 defconfig，并参考官方 Armada 与 ROCKNIX 的 SM8250 配置，才更容易区分缺失基础依赖和真实板级问题。

经验：使用有依据的配置基线；一个诊断镜像通过，不代表更大的程序、图形会话或多核调度已经可靠。旧配置和新配置的区别需要可追溯。

## 3. boot 容器细节会影响整个系统

本机的旧打包路径误保留原厂 Android RTIC 元数据，导致后续内存保护异常。移除末尾额外 173 字节 RTIC 树、保留三个原厂硬件 DTB 后，标准配置内核能够正常启动。这个缺陷在表面上表现为用户空间崩溃、CPU 卡住或启动失败，很容易被误判成单个应用的问题。

专用 Recovery 又有独立的容器要求：需要保留原厂 recovery DTBO 等结构。普通 boot 的打包方式不能直接当作 Recovery 的完整模板。

经验：解析和校验实际打包结果，检查嵌入的内核、initramfs、DTB 与源码配置是否一致；不要只检查构建目录中的文件。

## 4. “GPU 初始化”与“桌面可用”之间有很多层

本机经历过只显示四色条、灰屏、黑屏、随后才到可交互桌面的阶段。Mesa 能创建 FD650 上下文，并不能证明面板输出已经正确。早期 splash 持有 DRM 设备时，也会影响独立 Plasma 接管。

验证顺序可拆成：显示时序与面板命令 → 实际像素输出 → GPU 渲染回读 → 合成器提交 → 物理画面 → 触摸与窗口操作。每一步都有不同的证据。

## 5. 桌面和游戏模式需要一致的会话管理

官方切换工具依赖 SDDM。如果系统用自定义目标直接启动 Plasma，点击切换后可能只退出桌面，而没有服务来启动 Steam 会话。本机为合并 GPU/KMS 配置接入 SDDM，同时保留旧分离配置的直接桌面回退。

进程存在不能替代用户操作验证。切换成功后还需要检查正常重启是否自动进入预期会话，以及电源、网络、输入和插件是否一同启动。

## 6. 手柄在 Steam 菜单可用，不代表游戏收到手柄

本机蓝牙手柄在 Steam 菜单可以操作，但部分游戏没有方向键和 A 键。定位到内核缺少 uinput：Steam 无法建立供游戏使用的虚拟手柄。补齐精确 ABI 的模块后完成游戏内验证，后续内核改为内置该功能。

定位时应分别检查蓝牙连接、原始输入事件、Steam 菜单、虚拟输入设备和游戏读取。这比反复重新配对更容易缩小范围。

## 7. 休眠必须区分软件关屏、CPU idle 与系统 suspend

模拟休眠、CPU 空闲状态、s2idle 和 SoC 深度低功耗是不同层级。本机 CPU idle 计数已增长，RTC 定时返回也成功过，但原生休眠的电源键唤醒仍失败，并伴随触屏 I2C 错误和服务 watchdog。因此继续使用模拟休眠，不宣称深度待机通过。

另一次唤醒后的电池图标消失，实际是 KWin 崩溃后 Powerdevil 没有恢复；底层电量仍能读取。更新 KWin 并调整电源管理服务恢复策略后完成受控回归。显示、桌面服务和底层供电必须分开定位。

## 8. 存储迁移与恢复需要成套设计

用户希望只保留一套系统，因此最终在 GPT 层面合并原 Android super 空间，形成连续根分区。这个过程涉及已有小分区迁移、双份 GPT、槽位属性和 bootloader 对分区表的重写行为。

迁移后还出现过空 GPT 槽位兼容问题；CRC 正确不等于分区语义正确。检查必须覆盖分区名称、GUID、范围、属性、数据复制哈希和恢复入口。保留固件、校准与备用 Recovery 是恢复设计的一部分。

本文不提供可直接套用到另一台手机的分区写入命令。

## 9. 公开进度应明确哪些只是绕过

- 《杀戮尖塔》关闭 Java JIT 后能进入中文菜单，补丁说明页面仍闪烁；这是兼容绕过，不能标记为完整修复。
- 《茶杯头》后续成功启动，但最初偶发失败没有确定根因。
- KWin 新版本通过了针对旧故障的受控回归，长期稳定性还需使用观察。
- 不同临时内核与已安装内核必须分开记录；只有写入、回读、正常重启及功能验收完成后，才提升安装状态。

## USB 调试可用之后，还需要单独适配主机模式

连接电脑时能读日志，只验证了手机作为 USB 设备的路径。HUB 需要 Type-C 角色判断、VBUS 供电、主机控制器和外设输入驱动共同工作。本机按原厂连线启用双角色后，先用无线 SSH 观察无供电 HUB 与键鼠枚举，再安装并验证插着 HUB 正常开机。这个过程保留了旧启动镜像和 Recovery。

本轮键鼠实机通过，USB 手柄仍待游戏内验证。记录接入的是蓝牙手柄还是 USB 接收器，可以避免把两条独立链路的成功混在一起。详见 [USB HUB 记录](USB-HOST.md)。
